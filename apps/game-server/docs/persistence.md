## Старт узла

1. Аренда `EntityId` из БД (граница выше всех записей и надгробий), аренда партиции с эпохой.
2. Состояние шарда (`initShardState`), часы мира, секции журнала текущего и следующего месяца.
3. Партиция регистрируется в `LOADING` (вход — `4128 PERSIST_WORLD_NOT_READY`), загружается из БД, затем `hydrate`.
4. Отметки изменений, фоновое сохранение (`PERSIST_FLUSH_INTERVAL_MS`), координатор критических транзакций, выдача стартового набора при первом входе, таймеры.

## Остановка

Сессии выходят (каждый герой сохраняется срочно, ≤ 5 с) → финальное сохранение (`PERSIST_SHUTDOWN_FLUSH_MS`) → таймеры и состояние шарда → освобождение аренды партиции.

## Критическая транзакция

Фаза-владелец механики описывает операцию (`CriticalTx`): участники, данные запроса для `payloadHash`, план по снимку участников (`upserts`, `deletes`, `minted`/`burned`, события журнала). Координатор блокирует участников по возрастанию `EntityId`, проверяет баланс стопок по ключам контента, включает несохранённые изменения участников и их контейнеров в ту же транзакцию, коммитит с проверкой эпохи и только затем меняет память. Обработчики намерений проверяют `critical.guard(id)`.

## Ограничения до следующих фаз

- Правила обмена, банка, торговцев — P21; здесь только координатор и типы операций.
- Банк героя — размещение `bank` с родителем-героем; полноценный банк — P21.
- Ключи контента существ и предметов, созданных без данных, — заглушка `<вид>.unknown` до P13/P19.
