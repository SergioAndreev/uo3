# Спецификация: world/static-world-data

## Purpose

Определяет хранилище данных плана Duskmarch в памяти: загрузку из пакета ассетов P02, каталог объектов и запросы клеток, опор, потолков, размещения и шага, общие для сервера и клиента.

## ADDED Requirements

### Requirement: Загрузка плана из пакета
Хранилище MUST загружать план из индекса мира и чанков пакета, проверяя SHA-256 каждого чанка по индексу и декодируя его строго. Несовпадение хэша SHALL отклонять загрузку с кодом `WORLD_CHUNK_HASH` и ключом чанка, ошибка формата — с кодом формата чанка. После загрузки хранилище MUST отвечать на запросы без чтения файлов.

#### Scenario: Загрузка синтетического плана
- **WHEN** загружается пакет `proving`
- **THEN** хранилище сообщает план `proving` размером 64×64 и 4 чанка

#### Scenario: Подменённый чанк
- **WHEN** байты одного чанка не совпадают с хэшем индекса
- **THEN** загрузка отклоняется с `WORLD_CHUNK_HASH`

### Requirement: Каталог объектов
Каталог MUST сопоставлять ключ контента модели с высотой в шагах и ролью: `prop` (не мешает), `obstacle` (занимает высоту от основания до вершины), `platform` (вершина — опора). Флаги объекта в чанке SHALL дополнять роль: `impassable` делает объект препятствием, `standable` — опорой, `roof` — потолком над клеткой. Неизвестный ключ при загрузке MUST сообщаться ошибкой `WORLD_UNKNOWN_OBJECT`.

#### Scenario: Неизвестная модель
- **WHEN** чанк содержит объект `model.unknown`, которого нет в каталоге
- **THEN** загрузка отклоняется с `WORLD_UNKNOWN_OBJECT` и координатами объекта

### Requirement: Опоры и потолок в колонне клетки
Запрос опор MUST возвращать упорядоченные по высоте опоры клетки: пол клетки при флаге `standable` и вершины объектов-платформ. Запрос потолка MUST возвращать наименьшую высоту основания препятствия или потолка выше заданной высоты либо отсутствие потолка. Клетка вне плана SHALL возвращать пустой список.

#### Scenario: Низкий потолок стенда
- **WHEN** запрашивается потолок над высотой `0` в клетке стенда `low-ceiling`
- **THEN** результат — `6`

### Requirement: Размещение сущности
Проверка размещения MUST разрешать сущность ростом `height` на высоте `h`, только если на `h` есть опора, в диапазоне `[h, h + height)` нет препятствий, а потолок не ниже `h + height`. Клетки без опоры (глубокая вода, стена) SHALL отклоняться.

#### Scenario: Рост под потолком
- **WHEN** проверяется герой ростом `7` в клетке стенда `low-ceiling` на высоте `0`
- **THEN** размещение отклоняется: потолок `6` ниже `7`, а сущность ростом `6` помещается

#### Scenario: Глубокая вода и стена
- **WHEN** проверяется размещение в клетках стендов `deep-water` и `wall-window`
- **THEN** оба размещения отклоняются

### Requirement: Шаг к соседней клетке
Проверка шага MUST принимать исходную позицию и направление и возвращать высоту назначения или отказ с причиной: `out-of-realm`, `no-surface`, `too-high` (подъём больше `climb` шагов), `blocked` (размещение невозможно), `corner` (диагональ срезает угол: одна из двух ортогональных соседних клеток непроходима). Из нескольких опор MUST выбираться наивысшая, на которую можно подняться.

#### Scenario: Лестница
- **WHEN** герой с подъёмом `2` шагает на восток по клеткам стенда `stairs` начиная с высоты `0`
- **THEN** каждый шаг разрешён, высоты назначения — `2, 4, 6, 8`

#### Scenario: Слишком высокая ступень
- **WHEN** герой с подъёмом `1` шагает с первой ступени `stairs` на вторую
- **THEN** шаг отклоняется с причиной `too-high`

#### Scenario: Срез угла стены
- **WHEN** герой шагает по диагонали так, что одна из ортогональных соседних клеток — стена стенда `wall-window`
- **THEN** шаг отклоняется с причиной `corner`
