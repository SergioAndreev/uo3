# Спецификация: ui/gump-framework

## Purpose

Определяет серверно-декларативный фреймворк гампов (Gumps): протокол открытия, обновления и закрытия диалоговых окон, безопасный парсер языка разметки, многостраничную навигацию, интерактивные элементы управления и детерминированную валидацию ответов игрока на сервере. Гарантирует защиту от подделки идентификаторов кнопок и переключателей, автоматическое закрытие контекстных окон при потере доступа и консистентный рендеринг из клиентских атласов и CC0-заглушек.

## ADDED Requirements

### Requirement: Серверно-декларативный протокол открытия и закрытия гампов
Сервер SHALL открывать гамп пакетом с `gumpInstanceId`, `gumpTypeId`, `contextSerial`, координатами `(x, y)`, флагами (`closable`, `movable`, `disposable`, `modal`), строкой разметки и массивом строк. Повторное открытие с тем же `gumpTypeId` и `contextSerial` MUST атомарно заменять окно без сброса его текущей позиции, а пакет закрытия MUST удалять экземпляр за 1 кадр.

#### Scenario: Открытие нового серверного гампа
- **WHEN** сервер отправляет пакет открытия гампа с `gumpTypeId = 0x01A0`, `gumpInstanceId = 1042`, координатами `(120, 80)` и валидной строкой разметки
- **AND** у клиента нет открытого гампа с `gumpTypeId = 0x01A0` для данного `contextSerial`
- **THEN** клиент создаёт окно гампа в позиции `(120, 80)`, регистрирует `gumpInstanceId = 1042` в активном стеке окон и отрисовывает элементы страницы `0` и `1`

#### Scenario: Горячее обновление открытого гампа того же типа и контекста
- **WHEN** у клиента открыт гамп с `gumpTypeId = 0x01A0` и `contextSerial = 0x40000100`, перемещённый игроком в координаты `(340, 210)`
- **AND** сервер присылает новый пакет открытия с тем же `gumpTypeId` и `contextSerial`, но новым `gumpInstanceId = 1043`
- **THEN** клиент заменяет содержимое и `gumpInstanceId` окна на `1043`, сохраняя пользовательскую позицию `(340, 210)` без мерцания

### Requirement: Безопасный парсер языка разметки и таблицы строк гампа
Клиент и сервер SHALL разбирать разметку гампа без динамического выполнения кода, поддерживая команды `page`, `resizepic`, `gumppic`, `gumppictiled`, `checkertrans`, `text`, `croppedtext`, `htmlgump`, `button`, `checkbox`, `radio`, `textentry`, `tilepic`, `tilepichue` и `tooltip`. Ссылки на индекс текста вне массива строк или неизвестные директивы MUST отклоняться с `ERR_GUMP_MALFORMED_LAYOUT`.

#### Scenario: Корректный разбор композитной разметки и HTML-подмножества
- **WHEN** клиент получает разметку с `resizepic`, `checkertrans`, `text` и `htmlgump`, содержащим теги `<BASEFONT>`, `<CENTER>`, `<B>`, `<I>` и `<COLOR>`
- **AND** все индексы строк находятся в пределах длины переданного массива строк (до `256` элементов)
- **THEN** парсер строит неизменяемое дерево элементов за время не более `2 мс`, а в `htmlgump` применяются только разрешённые теги форматирования без выполнения скриптов

#### Scenario: Отклонение разметки с выходом индекса строки за границы
- **WHEN** в команде `{ text 20 20 1152 99 }` указан индекс строки `99`, а таблица строк содержит только `5` элементов
- **AND** пакет поступает на вход валидатора протокола или клиентского парсера
- **THEN** парсер отклоняет пакет с кодом `ERR_GUMP_MALFORMED_LAYOUT`, записывает предупреждение в диагностический лог и не открывает повреждённое окно

### Requirement: Многостраничная навигация, группы радиокнопок и поля ввода
Клиент SHALL отрисовывать элементы страницы `0` как общий фон на всех страницах, а элементы страницы `N >= 1` — только когда активна страница `N`. Кнопки типа `PageButton` (`buttonType = 0`) MUST переключать страницу локально без сетевого пакета, `radio` MUST обеспечивать выбор ровно одного элемента в группе, а `textentry` MUST ограничивать длину по `maxChars` (`1..255`).

#### Scenario: Локальное переключение страницы без обращения к серверу
- **WHEN** игрок нажимает кнопку с `buttonType = 0` и `param = 3` на странице `1` открытого гампа
- **AND** в дереве разметки определена страница `3`
- **THEN** клиент мгновенно переключает отображение на страницу `3`, сохраняя видимыми фоновые элементы страницы `0`, и не отправляет сетевой пакет на сервер

#### Scenario: Ограничение ввода текста и работа группы радиокнопок
- **WHEN** игрок выбирает радиокнопку `switchId = 202` в группе `group = 1` (где ранее была выбрана `201`) и вводит строку в поле `textentry` с `maxChars = 16`
- **AND** длина вводимого текста превышает `16` символов
- **THEN** радиокнопка `201` автоматически снимается, `202` активируется, а текстовое поле усекает ввод ровно до `16` печатных символов

### Requirement: Детерминированная сериализация и валидация ответа гампа
При нажатии `ReplyButton` (`buttonType = 1`) или закрытии гампа с `buttonId = 0` клиент SHALL отправлять ответ с `gumpInstanceId`, `gumpTypeId`, `buttonId`, списком выбранных `switches` (до `64` шт.) и словарём `textEntries` (до `16` полей). Сервер MUST проверять наличие всех идентификаторов в исходной схеме сессии и отклонять поддельные ответы с `ERR_GUMP_INVALID_RESPONSE`.

#### Scenario: Успешная обработка валидного ответа гампа сервером
- **WHEN** игрок нажимает `ReplyButton` с `buttonId = 10` при отмеченном чекбоксе `switchId = 5` и заполненном поле `entryId = 1`
- **AND** сервер находит активную сессию `gumpInstanceId` с разрешёнными `buttonId = 10`, `switchId = 5` и `entryId = 1`
- **THEN** сервер удаляет одноразовую сессию гампа, передаёт нормализованные данные в доменный обработчик и закрывает гамп у клиента

#### Scenario: Блокировка поддельного идентификатора кнопки или переключателя
- **WHEN** модифицированный клиент отправляет ответ с `buttonId = 999` или `switchId = 777`, которые отсутствовали в отправленной сервером разметке данного `gumpInstanceId`
- **AND** сервер выполняет проверку по схеме активной сессии гампа
- **THEN** сервер отвергает намерение с кодом `ERR_GUMP_INVALID_RESPONSE`, закрывает сессию `gumpInstanceId` и увеличивает счётчик нарушений протокола

### Requirement: Автозакрытие контекстных гампов по дистанции и состоянию
Если гамп привязан к мировой сущности через `contextSerial` и `maxDistanceTiles`, сервер SHALL автоматически аннулировать сессию и отправлять пакет закрытия с причиной `OUT_OF_RANGE`, `CONTEXT_DESTROYED` или `ACTOR_DEAD`, как только дистанция Чебышёва превысит `maxDistanceTiles`, сущность покинет AOI или персонаж погибнет.

#### Scenario: Автоматическое закрытие гампа при отходе от объекта
- **WHEN** у персонажа открыт контекстный гамп объекта с `contextSerial = 0x40000250` и `maxDistanceTiles = 2`
- **AND** персонаж делает шаг, увеличивающий дистанцию Чебышёва до объекта до `3` тайлов
- **THEN** на ближайшем тике симуляции (`50 мс`) сервер аннулирует сессию гампа и отправляет клиенту пакет закрытия с причиной `OUT_OF_RANGE`

#### Scenario: Отклонение ответа гампа после смерти персонажа
- **WHEN** персонаж погибает (`Hits = 0`) при открытом контекстном гампе с флагом `aliveOnly = true`
- **AND** клиент успевает отправить `GumpResponseIntent` до получения пакета закрытия
- **THEN** сервер отклоняет ответ с кодом `ERR_GUMP_SESSION_EXPIRED` и принудительно закрывает гамп на клиенте

### Requirement: Рендеринг элементов гампа из OPFS-атласов и CC0-заглушек
Клиент SHALL отрисовывать графические примитивы гампа (`gumppic`, `resizepic` из 9 сегментов, `tilepic`) из OPFS-атласов, сгенерированных при импорте, с применением палитры `hues` (`1..3000`) и полупрозрачной маски `checkertrans` (`alpha = 0.5`). При отсутствии пользовательского ассета клиент MUST без ошибок подставлять детерминированную CC0-заглушку с теми же габаритами.

#### Scenario: Отрисовка масштабируемого фона resizepic из 9 слайсов
- **WHEN** в разметке задан `{ resizepic 0 0 5054 320 240 }`
- **AND** текстуры с базовым идентификатором `5054..5062` присутствуют в OPFS-атласе или наборе CC0-заглушек
- **THEN** клиент собирает рамку `320×240 px` из 4 угловых, 4 бордюрных и 1 центрального тайлового сегмента без растяжения углов

#### Scenario: Фолбэк на CC0-заглушку при отсутствии спрайта гампа
- **WHEN** клиент запущен в CI или dev-режиме без импортированных проприетарных файлов и открывает гамп с `gumpArtId = 0x0800`
- **AND** ассет `0x0800` отсутствует в пользовательском кэше
- **THEN** рендерер подставляет синтетический CC0-спрайт соответствующих размеров из `@uo3/ui-kit` без выброса исключений и без блокировки интерактивных кнопок

### Requirement: Стек Z-order, модальность и закрытие правым кликом
Менеджер окон SHALL поддерживать детерминированный стек `Z-order` открытых гампов (до `32` одновременно открытых серверных гампов): клик по окну MUST поднимать его на вершину стека. Правый клик по области гампа с флагом `closable = true` (или клавиша `Escape` при флаге `disposable = true`) MUST закрывать верхний гамп и отправлять на сервер ответ с `buttonId = 0`.

#### Scenario: Закрытие разрешённого гампа правым кликом мыши
- **WHEN** игрок нажимает правую кнопку мыши по фону активного гампа с флагом `closable = true`
- **AND** курсор не находится в режиме активного целеуказания `TargetCursor`
- **THEN** клиент закрывает окно гампа и отправляет на сервер пакет ответа с `buttonId = 0` и пустым списком выбранных действий

#### Scenario: Запрет закрытия неразрешённого модального гампа
- **WHEN** открыт серверный гамп с флагами `closable = false` и `modal = true`
- **AND** игрок нажимает правую кнопку мыши по фону гампа или клавишу `Escape`
- **THEN** окно остаётся открытым на вершине `Z-order`, клики мимо него по другим гампам блокируются, а пакет закрытия не отправляется
