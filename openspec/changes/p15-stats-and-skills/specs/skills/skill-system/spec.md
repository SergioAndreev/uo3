# Спецификация: skills/skill-system

## Purpose

Данная спецификация определяет канонический реестр 49 навыков UO:R, представление базовых и эффективных значений в десятых долях (`0..1000`), правила активации и глобального кулдауна активных навыков, таргетинг с проверкой дистанции и 3D LOS, вероятностную модель проверки успеха, прерывание действий, расчёт титула персонажа и контракт делегирования доменных эффектов.

## ADDED Requirements

### Requirement: Канонический реестр 49 навыков UO Renaissance
Система SHALL определять ровно 49 канонических навыков UO:R (`SkillId 0..48`) в декларативной схеме контента с обязательными полями: идентификатор, символьный ключ, категория, флаг `isActive`, веса характеристик (`strWeight`, `dexWeight`, `intWeight`), базовый кулдаун `cooldownMs`, режим таргетинга и титул профессии.

#### Scenario: Валидация полноты реестра из 49 навыков при старте
- **WHEN** сервер или клиент инициализирует реестр контента навыков
- **AND** проверяет загруженные определения по схеме
- **THEN** реестр содержит все 49 уникальных `SkillId` от `0` до `48` без пропусков, где у каждого навыка сумма весов статов больше `0`

#### Scenario: Отклонение некорректного идентификатора навыка
- **WHEN** клиент отправляет намерение использования или изменения блокировки для `SkillId = 49` или `SkillId = -1`
- **AND** сервер валидирует входящий пакет
- **THEN** запрос отклоняется с кодом ошибки `ERR_INVALID_SKILL_ID` без обращения к состоянию персонажа

### Requirement: Хранение значений навыков в десятых долях и эффективный расчёт
Сервер SHALL хранить для каждого персонажа все 49 навыков в целочисленных десятых долях (`BaseValue` от `0` до `1000`, что соответствует `0.0..100.0`) и вычислять `EffectiveValue = clamp(BaseValue + TempSkillBonusTenths, 0, 1200)`.

#### Scenario: Расчёт эффективного навыка с учётом бонуса экипировки или баффа
- **WHEN** персонаж имеет `BaseValue = 855` (`85.5`) по навыку и активный бонус `+50` десятых (`+5.0`)
- **AND** сервер запрашивает значение навыка для проверки успеха
- **THEN** `EffectiveValue` возвращается равным `905` (`90.5`), а `BaseValue` для расчёта капа остаётся равным `855`

#### Scenario: Защита эффективного значения от выхода в отрицательную область
- **WHEN** персонаж с `BaseValue = 30` (`3.0`) получает временный штраф `-100` десятых (`-10.0`)
- **AND** сервер вычисляет `EffectiveValue`
- **THEN** `EffectiveValue` ограничивается снизу значением `0`

### Requirement: Использование активных навыков и глобальный кулдаун действия
Сервер SHALL разрешать прямую активацию намерением только для навыков с `isActive = true` для живых персонажей; попытка активировать пассивный навык MUST возвращать `ERR_SKILL_NOT_USABLE`, а успешный запуск активного навыка MUST устанавливать глобальный кулдаун навыков (`1000..10000` мс по конфигурации навыка), блокирующий повторную активацию кодом `ERR_SKILL_COOLDOWN`.

#### Scenario: Попытка прямой активации пассивного навыка
- **WHEN** клиент отправляет намерение `UseSkillIntent` для пассивного навыка (`Tactics`, `Parrying` или `Resisting Spells`, где `isActive = false`)
- **AND** сервер проверяет метаданные навыка в реестре
- **THEN** сервер отклоняет намерение с кодом `ERR_SKILL_NOT_USABLE` и не запускает глобальный кулдаун

#### Scenario: Отказ в активации навыка во время активного кулдауна
- **WHEN** персонаж активировал навык `Hiding` с кулдауном `10000` мс
- **AND** через `2500` мс клиент отправляет новое намерение `UseSkillIntent` для любого активного навыка
- **THEN** сервер отклоняет запрос с кодом `ERR_SKILL_COOLDOWN` и возвращает оставшееся время кулдауна `7500` мс

#### Scenario: Запрет использования навыков призраком или замороженным персонажем
- **WHEN** персонаж мёртв (`Hits == 0`) либо находится под эффектом паралича/заморозки
- **AND** клиент отправляет намерение `UseSkillIntent`
- **THEN** сервер отклоняет запрос с кодом `ERR_CHARACTER_DEAD` или `ERR_CHARACTER_BUSY`

### Requirement: Вероятностная проверка успеха по кривой сложности
Сервер SHALL вычислять шанс успеха навыка в базисных пунктах (`0..10000`) по линейной интерполяции UO:R `chanceBp = clamp(floor((EffectiveValue - minSkillTenths) * 10000 / max(1, maxSkillTenths - minSkillTenths)), 0, 10000)` и считать проверку успешной, если бросок PRNG `roll` (`0..9999`) строго меньше `chanceBp`.

#### Scenario: Точный расчёт 50-процентного шанса в середине диапазона сложности
- **WHEN** действие требует диапазон навыка `minSkillTenths = 400` (`40.0`) и `maxSkillTenths = 900` (`90.0`), а `EffectiveValue` персонажа равен `650` (`65.0`)
- **AND** сервер вычисляет вероятность успеха
- **THEN** `chanceBp` равен `5000` (`50.00%`), и проверка успешна при `roll = 4999` и неуспешна при `roll = 5000`

#### Scenario: Автоматический провал ниже минимального порога и успех выше максимального
- **WHEN** действие имеет `minSkillTenths = 500`, `maxSkillTenths = 1000`
- **AND** проверку проходят персонаж A с `EffectiveValue = 499` и персонаж B с `EffectiveValue = 1000`
- **THEN** для персонажа A `chanceBp = 0` (всегда провал), а для персонажа B `chanceBp = 10000` (всегда успех)

### Requirement: Целеуказание и проверка дистанции и видимости для навыков
Для активных навыков, требующих цель, сервер SHALL открывать резервацию курсора цели с таймаутом `30000` мс и при получении ответа проверять тип цели, дистанцию Чебышёва (`<= maxRangeTiles`) и 3D LOS; при нарушении условий сервер MUST отклонять действие кодами `ERR_TARGET_TIMEOUT`, `ERR_TARGET_INVALID`, `ERR_OUT_OF_RANGE` или `ERR_NO_LOS`.

#### Scenario: Успешное применение целевого навыка в пределах дистанции и 3D LOS
- **WHEN** персонаж активирует целевой навык `Anatomy` (`maxRangeTiles = 8`, `requiresLos = true`) и сервер выдаёт курсор цели
- **AND** клиент в течение `3000` мс указывает живого моба на расстоянии `6` тайлов при наличии прямой видимости 3D DDA LOS
- **THEN** сервер закрывает курсор, запускает кулдаун навыка и выполняет проверку успеха `Anatomy`

#### Scenario: Отклонение целевого навыка при отсутствии линии видимости или превышении дистанции
- **WHEN** персонаж с активным курсором навыка (`maxRangeTiles = 8`, `requiresLos = true`) выбирает цель на расстоянии `11` тайлов либо за каменной стеной без 3D LOS
- **AND** сервер проверяет геометрию между персонажем и целью
- **THEN** действие отклоняется с кодом `ERR_OUT_OF_RANGE` или `ERR_NO_LOS` без выполнения эффекта навыка

### Requirement: Прерывание и отмена активного использования навыка
Если навык имеет длительность выполнения (`castOrChannelTicks > 0`) или ожидает выбора цели, сервер SHALL немедленно прерывать его с кодом `ERR_SKILL_INTERRUPTED` при смерти персонажа, получении паралича, смене боевого режима или превышении допустимого числа шагов движения.

#### Scenario: Прерывание потокового навыка при получении урона или движении
- **WHEN** персонаж выполняет навык с задержкой завершения `2000` мс и ограничением `maxMoveSteps = 0`
- **AND** до истечения `2000` мс персонаж делает шаг или погибает
- **THEN** сервер отменяет таймер завершения навыка, отправляет клиенту `ERR_SKILL_INTERRUPTED` и не применяет результирующий эффект

#### Scenario: Истечение 30-секундного таймаута ожидания курсора цели
- **WHEN** персонаж активировал целевой навык и получил запрос на выбор цели
- **AND** в течение `30000` мс клиент не отправил пакет выбора цели
- **THEN** сервер автоматически аннулирует резервацию курсора и уведомляет клиент кодом `ERR_TARGET_TIMEOUT`

### Requirement: Расчёт титула персонажа по ведущему навыку
Сервер SHALL детерминированно вычислять профессиональный титул персонажа по навыку с наибольшим `BaseValue` (при равенстве — с меньшим `SkillId`) согласно порогам: `< 300` без титула, `300..399` `Neophyte`, `400..499` `Novice`, `500..599` `Apprentice`, `600..699` `Journeyman`, `700..799` `Expert`, `800..899` `Adept`, `900..999` `Master`, `1000` `Grandmaster`.

#### Scenario: Присвоение титула Grandmaster при достижении 100.0
- **WHEN** максимальный навык персонажа `Swordsmanship` (`title = "Swordsman"`) достигает `BaseValue = 1000`
- **AND** сервер пересчитывает отображаемый титул профессии
- **THEN** персонажу присваивается титул `"Grandmaster Swordsman"`

#### Scenario: Разрешение ничьей между двумя равными навыками по меньшему SkillId
- **WHEN** у персонажа два самых высоких навыка имеют одинаковое значение `BaseValue = 750`: `SkillId = 1` (`Anatomy`, `"Scholar"`) и `SkillId = 25` (`Magery`, `"Mage"`)
- **AND** сервер определяет ведущий навык для титула
- **THEN** выбирается навык с меньшим `SkillId = 1`, и титул равен `"Expert Scholar"`

### Requirement: Детерминированные хуки делегирования доменных эффектов навыков
Ядро навыков SHALL централизованно выполнять валидацию состояния, кулдаун, таргетинг, расчёт `chanceBp`, бросок успеха и конвейер прироста, делегируя прикладной эффект конкретному доменному обработчику через единый контракт результата (`success`, `roll`, `chanceBp`, `effectiveSkillTenths`).

#### Scenario: Вызов зарегистрированного доменного обработчика после расчёта броска
- **WHEN** персонаж использует активный навык с зарегистрированным обработчиком эффекта
- **AND** ядро навыков завершает проверку дистанции, кулдауна и бросок PRNG
- **THEN** доменный обработчик вызывается ровно один раз с вычисленным контекстом броска, а расчёт прироста навыка и статов выполняется единым пайплайном ядра

#### Scenario: Безопасная отработка навыка-заглушки до подключения фаз P16-P20
- **WHEN** в тестовой среде активируется навык, чей прикладной обработчик ещё работает в режиме базовой резолюции P15
- **AND** проверка условий и бросок успеха проходят штатно
- **THEN** сервер корректно начисляет кулдаун, выполняет проверку прироста навыка/статов и возвращает клиенту детерминированный статус завершения
