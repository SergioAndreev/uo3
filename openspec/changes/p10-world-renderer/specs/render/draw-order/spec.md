# Спецификация: render/draw-order

## Purpose

Определяет канонический порядок перекрытия объектов мира Ultima Online: вычисление ключа сортировки по изометрической диагонали `(x + y)`, высоте `Z`, флагам `tiledata` и категориям сущностей, точное монотонное кодирование ключа в 24-битный буфер глубины для батчинга непрозрачной геометрии, а также раздельный отсортированный проход для полупрозрачных объектов без z-fighting.

## ADDED Requirements

### Requirement: Канонический первичный порядок перекрытия по изометрической диагонали
Первичным критерием перекрытия MUST служить изометрическая диагональ `diag = x + y`: при пересечении на экране объект с большим значением `x + y` SHALL перекрывать объект с меньшим значением `x + y`, воспроизводя направление взгляда камеры с юго-востока на северо-запад.

#### Scenario: Перекрытие персонажа передней стеной здания
- **WHEN** персонаж стоит на тайле `(20, 20, 0)` (`diag = 40`), а на тайле `(21, 20, 0)` (`diag = 41`) расположена стена высотой `20` единиц `Z`
- **THEN** пиксели стены перекрывают пиксели персонажа в области их экранного пересечения

#### Scenario: Персонаж перед задней стеной здания
- **WHEN** персонаж стоит на тайле `(20, 20, 0)` (`diag = 40`), а на тайле `(19, 20, 0)` (`diag = 39`) расположена стена высотой `20` единиц `Z`
- **THEN** пиксели персонажа полностью перекрывают пиксели стены

### Requirement: Внутритайловый приоритет по высоте Z, порогам tiledata и категории
Внутри одной диагонали порядок MUST определяться по `sortZ = priorityZ + threshold`, затем по `priorityZ`, затем по рангу категории (`Land < Static < Multi < DynamicItem < Mobile < Effect`). Порог `threshold` SHALL равен `0` для земли и плоских `Background` (`height = 0`), `1` для `Background` с `height > 0` и плоских `!Background` (`height = 0`), `2` для `!Background` с `height > 0` и мобайлов, и `3` для мировых эффектов.

#### Scenario: Стопка объектов на одном тайле (земля, ковёр, золото, стол, предмет на столе)
- **WHEN** на одном тайле `(15, 15)` находятся земля (`z = 0`), ковёр (`Background, h = 0, z = 0`), монеты (`!Background, h = 0, z = 0`), стол (`!Background, h = 6, z = 0`) и кубок на столе (`!Background, h = 0, z = 6`)
- **THEN** визуальный порядок снизу вверх строго соответствует цепочке «земля → ковёр → монеты → стол → кубок»

#### Scenario: Персонаж, стоящий на ковре и на ступеньках
- **WHEN** мобайл находится на тайле `(15, 15, z = 0)` поверх плоского пола (`Background, h = 1, z = 0`), а затем поднимается на ступеньку (`Bridge, z = 0, h = 4` → мобайл на `z = 2`)
- **THEN** в обоих положениях мобайл отображается строго поверх пола и ступеньки без утопания в статике

#### Scenario: Разрешение равенства sortZ в пользу большей базовой высоты priorityZ
- **WHEN** на одном тайле находятся плоский предмет на `z = 1` (`threshold = 1`, `sortZ = 2`) и высокий статический предмет на `z = 0` (`threshold = 2`, `sortZ = 2`)
- **THEN** объект с большей базовой высотой `z = 1` перекрывает объект с `z = 0`, строго совпадая с каноническим тай-брейкером UO

### Requirement: Резервирование детерминированных подслотов для слоёв мобайлов и стопок
Система кодирования глубины MUST выделять не менее `32` детерминированных подслотов в диапазоне мобайлов для упорядочивания тела, маунта и всех `24` слоёв экипировки (для P11), а также раздельные подслоты для множественных статических объектов, компонентов `multi` и дублирующего спрайта стопок предметов (`amount > 1`) на одном `(x, y, z)`.

#### Scenario: Упорядочивание слоёв экипировки на одном тайле
- **WHEN** подсистема визуализации мобайлов (P11) передаёт на один тайл `(10, 10, 0)` тело, штаны, тунику, плащ и оружие с последовательными индексами порядка слоёв `0..4`
- **THEN** каждый последующий слой получает строго больший ключ глубины и отрисовывается поверх предыдущего без мерцания

#### Scenario: Наложение второго спрайта стопки предметов
- **WHEN** стопка золота на `(10, 10, 0)` генерирует базовый и смещённый спрайты
- **THEN** смещённый спрайт получает подслот `+1` относительно базового и гарантированно перекрывает его независимо от порядка инстансов в буфере

### Requirement: Полный детерминизм и отсутствие z-fighting при совпадении координат
Для любых двух различных непрозрачных объектов с совпадающими `(x, y, z, threshold)` система MUST назначать строго различные, воспроизводимые подслоты (по исходному индексу статики, индексу компонента `multi` либо серийнику динамической сущности). Результат перекрытия SHALL не зависеть от порядка подачи батчей в GPU и не мерцать между кадрами.

#### Scenario: Два динамических предмета с одинаковыми координатами и высотой
- **WHEN** на тайле `(25, 25, 0)` лежат два предмета одного типа с серийниками `0x40000010` и `0x40000025`
- **THEN** предмет с большим серийником `0x40000025` стабильно отрисовывается поверх `0x40000010` на протяжении всех кадров и после пересборки батчей

#### Scenario: Перестановка порядка инстансов в пакете отрисовки
- **WHEN** массив инстансов непрозрачной статики перемешивается в произвольном порядке перед отправкой на GPU
- **THEN** результирующее изображение экрана побитово совпадает с изображением до перестановки благодаря аппаратному тесту глубины

### Requirement: Монотонное кодирование ключа в 24-битный буфер глубины без потери точности
Составной ключ `(relDiag ∈ [0..255], sortZ ∈ [0..259], subSlot ∈ [0..125])` MUST упаковываться в строго монотонное целое число диапазона `[0, 8 386 559]` (`< 2^23`) и преобразовываться в нормализованную глубину так, чтобы два соседних значения `k` и `k + 1` различались не менее чем на `2` дискретных шага `24`-битного буфера глубины без ошибок округления `float32`.

#### Scenario: Строгая монотонность на краях диапазона ключей
- **WHEN** вычисляются значения нормализованной глубины для пар соседних ключей `(0, 1)`, `(4 194 303, 4 194 304)` и `(8 386 558, 8 386 559)`
- **THEN** после квантования к `24`-битному целому буферу глубины (`[0, 16 777 215]`) каждое следующее значение строго меньше предыдущего минимум на `2` единицы

#### Scenario: Проверка переполнения диапазона подслотов на перегруженном тайле
- **WHEN** на одном тайле и одной высоте `Z` размещено больше статических объектов, чем выделено подслотов категории (например, `20` статических объектов)
- **THEN** индекс подслота безопасно зажимается к верхней границе своей категории, не выходя в соседнюю категорию и не нарушая порядок с мобайлами или соседним `sortZ`

### Requirement: Скользящая относительная база диагонали для полноразмерных карт 7168x4096
Для сохранения полной `24`-битной точности на любом участке фасета размером `7168×4096` (`x + y` до `11 264`) относительная диагональ MUST вычисляться как `relDiag = (x + y) - baseDiag`, где `baseDiag` привязывается к текущей позиции камеры так, чтобы видимое окно всегда располагалось в центре диапазона `[0..255]`. Объекты за пределами окна SHALL безопасно ограничиваться границами `[0, 255]`.

#### Scenario: Отрисовка в дальнем юго-восточном углу фасета Felucca
- **WHEN** камера перемещается к координате `(7150, 4080, 0)` (`x + y = 11 230`)
- **THEN** относительные ключи `relDiag` видимых тайлов центрируются вокруг `128`, сохраняя точность `24`-битной глубины идентичной координатам `(100, 100, 0)`

#### Scenario: Смена базовой диагонали при плавной ходьбе
- **WHEN** игрок перемещается на `1` тайл, сдвигая `baseDiag` на `+1`
- **THEN** относительный порядок всех видимых объектов остаётся неизменным, без визуальных скачков и без необходимости пересобирать геометрию чанков (сдвиг передаётся параметром кадра)

### Requirement: Согласование глубины наклонного рельефа и объектов на склонах
Меш земли на тайле `(x, y)` MUST сортироваться позади любого статического объекта, предмета или мобайла, размещённого на этом же тайле `(x, y)` на высоте `z >= landPriorityZ`, тогда как приподнятый холм переднего плана на `(x + 1, y + 1)` SHALL корректно перекрывать объекты, находящиеся за гребнем холма на меньшей высоте.

#### Scenario: Предмет и дерево на крутом склоне холма
- **WHEN** на наклонном тайле `(30, 30)` с перепадом углов `Z = 0..12` стоит дерево на `z = 6`
- **THEN** основание ствола дерева не разрезается треугольниками склона своего тайла `(30, 30)` и полностью видно поверх земли

#### Scenario: Персонаж, скрывающийся за гребнем холма
- **WHEN** персонаж стоит на `(30, 30, z = 0)`, а на переднем плане на `(32, 32)` возвышается холм с вершиной `z = 24`
- **THEN** гребень холма на `(32, 32)` (`diag = 64 > 60`) перекрывает нижнюю часть силуэта персонажа строго по линии склона

### Requirement: Раздельный отсортированный проход полупрозрачности
Непрозрачные и альфа-тестируемые спрайты (`alpha >= 0.5`) MUST рендериться в первом проходе с включёнными тестом и записью глубины в произвольном порядке батчей. Полупрозрачные объекты (`Translucent`, `AlphaBlend`, затухающие кроны, стены круга прозрачности, призраки) SHALL рендериться во втором проходе с тестом глубины, без записи глубины и со строгой сортировкой сзади-наперёд по ключу.

#### Scenario: Два перекрывающихся полупрозрачных витражных окна перед стеной
- **WHEN** позади находятся каменная стена (`diag = 40`), полупрозрачное синее стекло (`diag = 41`, `Translucent`) и полупрозрачное красное стекло (`diag = 42`, `Translucent`)
- **THEN** сначала рисуется стена в непрозрачном проходе, затем в проходе полупрозрачности строго сначала синее, затем красное стекло поверх него с корректным смешением цветов

#### Scenario: Полупрозрачный объект частично заслонён непрозрачной колонной
- **WHEN** полупрозрачный эффект или стекло (`diag = 40`) находится позади непрозрачной каменной колонны (`diag = 41`)
- **THEN** тест глубины отсекает закрытую колонной часть полупрозрачного объекта, а его открытая часть корректно смешивается с фоном
