# Design: P02 Пакет ассетов и чанки мира

## Context

P01 дала идентификаторы, пространство (план, клетка, высота в шагах 0,25 м, чанк 32×32), поверхности, флаги клеток, оттенки, ключи контента и `SeededRng`. ADR-002 и CONCEPT §5 запрещают чтение чужих форматов: пакет ассетов и чанки мира — собственные. Модели — glTF 2.0 (GLB), текстуры — KTX2, PNG или WebP, звук — Ogg.

## Goals / Non-Goals

**Goals:**
- Один формат данных мира для клиента, сервера и инструментов, изоморфный и строго проверяемый.
- Детерминированный синтетический мир для тестов без внешних файлов.
- Проверка лицензий и целостности каждой записи.

**Non-Goals:**
- Кэш и декодирование в браузере (P09), рендер (P10), высоты под объектами и линия видимости (P03).

## Decisions

### D1. Манифест JSON + файлы, адресуемые по ключу контента
Пакет — каталог с `pack.json` и файлами. Ключ контента (`model.test-crate`) — единственный способ сослаться на ассет из контента и чанков. Хэш SHA-256 каждой записи защищает от подмены и даёт ключ для кэша P09.
- *Альтернатива — один бинарный архив:* неудобно обновлять частично, сложнее кэшировать по записям.

### D2. Чанк без сжатия, little-endian, фиксированные записи
Чанк 32×32 — 8 КиБ клеток плюс объекты; без сжатия декодирование — это `DataView` без аллокаций, одинаковое в браузере и Node.js. Little-endian совпадает с порядком байтов GPU и типизированных массивов. Флаг сжатия в заголовке оставлен для следующей версии.
- *Альтернатива — JSON:* в 10–20 раз больше и медленнее разбирается.

### D3. CRC-32 для повреждений, SHA-256 для подлинности
CRC-32 (полином `0xEDB88320`) в заголовке ловит повреждение при чтении одного файла без манифеста; SHA-256 в манифесте подтверждает, что файл тот самый.

### D4. Каноническое кодирование
Таблица ключей — в порядке первого появления в отсортированных объектах; объекты сортируются по `(ly, lx, h, key)`; резервные поля нулевые. Одинаковые данные дают одинаковые байты и одинаковый хэш, поэтому синтетический мир воспроизводим побайтно.

### D5. Палитра вычисляется, а не рисуется
256 оттенков: индекс 0 — естественный цвет; `1 + t × 17 + s` — тон `t ∈ 0..14` с углом `35 + t × 15`° (янтарь → индиго 245°), ступень `s ∈ 0..16` с яркостью `12 + s × 5` % и насыщенностью 70 %. Преобразование HSL → sRGB выполняется в целых тысячных, чтобы результат совпадал на всех платформах; эталон хранится в репозитории.

### D6. SHA-256 переезжает в `@duskmarch/domain`
Хэш нужен `asset-formats`, а граф границ P00 разрешает ему зависеть только от `domain`. Реализация из P01 переносится в `domain/util`, `rules` реэкспортирует её; поведение и тесты не меняются.

### D7. Генератор в `asset-formats`, а не в `test-kit`
`apps/asset-tool` не может зависеть от `test-kit` (только тесты). Генератор изоморфен и детерминирован, поэтому живёт в `@duskmarch/asset-formats/synthetic`; `test-kit` строит из него фикстуры.

### D8. Процедурные GLB-модели
Заглушки строятся из боксов (ящик, колонна, стена, дерево — ствол и крона, манекен — туловище и голова) с позициями, нормалями и индексами `uint16`, одним материалом цвета палитры. Писатель GLB — около сотни строк без зависимостей.

### D9. PNG только в CLI
Превью `radar` кодирует PNG через `node:zlib` в `apps/asset-tool`; изоморфные пакеты не получают Node API.

## Architecture & Contracts

### Заголовок чанка (24 байта, little-endian)
| Смещение | Тип | Поле |
| --- | --- | --- |
| 0 | `u8[4]` | магия `DMCK` |
| 4 | `u16` | версия = 1 |
| 6 | `u16` | флаги: бит 0 — сжатие (0 в версии 1), остальные 0 |
| 8 | `u8` | план |
| 9 | `u8` | резерв = 0 |
| 10 | `u16` | `cx` |
| 12 | `u16` | `cy` |
| 14 | `u16` | число ключей |
| 16 | `u16` | число объектов (до 4 096) |
| 18 | `u16` | резерв = 0 |
| 20 | `u32` | CRC-32 байтов с 24 до конца |

### Тело чанка
| Блок | Размер | Поля |
| --- | --- | --- |
| Клетки | 1 024 × 8 | `surface u8` (индекс `SURFACES`), `tint u8`, `h i16`, `flags u32` |
| Ключи | Σ(1 + длина) | `len u8`, ASCII ключа контента |
| Объекты | N × 10 | `key u16`, `lx u8`, `ly u8`, `h i16`, `rotation u8` (0..3), `tint u8`, `flags u16` |

### Манифест пакета (`pack.json`)
```json
{
  "schemaVersion": 1,
  "id": "pack.synthetic-field",
  "version": "1.0.0",
  "entries": [
    {
      "key": "chunk.dawn.x0.y0",
      "kind": "chunk",
      "path": "chunks/dawn/0_0.dmck",
      "sha256": "…",
      "bytes": 8306,
      "license": "synthetic-generated",
      "source": "asset-tool generate-world --preset field --seed 42"
    }
  ]
}
```

Ключ чанка — `chunk.<план>.x<cx>.y<cy>`, путь — `chunks/<план>/<cx>_<cy>.dmck`. Пресет `field` пишет план `dawn`, пресет `proving` — план `proving`.

### Индекс мира (`world.json`)
```json
{
  "schemaVersion": 1,
  "realm": { "id": 0, "key": "dawn" },
  "width": 256,
  "height": 256,
  "chunkSize": 32,
  "chunks": [{ "cx": 0, "cy": 0, "key": "chunk.dawn.x0.y0", "sha256": "…" }]
}
```

### Модули `@duskmarch/asset-formats`
`pack/` (схема, проверка, отпечаток, загрузчик), `chunk/` (кодек, CRC-32, доступ к клеткам), `world/` (индекс), `palette/`, `glb/` (писатель и проверка), `synthetic/` (шум, стенды, пресеты, сборка пакета). Подпути экспорта: `/pack`, `/chunk`, `/world`, `/palette`, `/glb`, `/synthetic`.

### Коды ошибок
Пакет: `ASSET_SCHEMA`, `ASSET_KIND_EXTENSION`, `ASSET_PATH_UNSAFE`, `ASSET_DUPLICATE_KEY`, `ASSET_DUPLICATE_PATH`, `ASSET_LICENSE`, `ASSET_TOO_LARGE`, `ASSET_MISSING`, `ASSET_HASH_MISMATCH`, `ASSET_SIZE_MISMATCH`, `ASSET_UNLISTED` (предупреждение), `ASSET_UNKNOWN_KEY`. Чанк: `CHUNK_MAGIC`, `CHUNK_VERSION`, `CHUNK_TRUNCATED`, `CHUNK_CRC`, `CHUNK_VALUE`. Мир: `WORLD_SCHEMA`, `WORLD_GRID`, `WORLD_DUPLICATE`.

## Risks / Trade-offs

- **Рост объектов в чанке** → лимит 4 096 объектов и 64 КиБ на файл; крупные постройки разбиваются на части в P23.
- **Несжатые чанки занимают место** → план 4096×4096 — 16 384 чанка по ~8 КиБ, около 130 МиБ; сжатие добавляется флагом заголовка без смены раскладки, кэш P09 хранит распакованное.
- **Ошибка в HSL → sRGB** → эталон палитры в репозитории и проверка границ.

## Migration Plan

Новый формат без существующих данных. Заглушка `asset-formats` из P00 заменяется. Откат — `git revert`.

## Open Questions

- Сжатие чанков (deflate или собственное RLE) выбирается в P10 по замерам загрузки.
