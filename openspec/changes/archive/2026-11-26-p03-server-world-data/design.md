# Design: P03 Серверные данные статического мира

## Context

P02 дала пакет ассетов, чанки `DMCK` (поверхность, оттенок, высота, флаги клеток, объекты с ключами контента) и синтетический план `proving` со стендами. P01 — пространство, направления, флаги клеток, профиль правил (рост 7 шагов, подъём 2, радиус интереса 20). Матрица границ P00: `asset-formats → domain`, `rules → domain`; приложения могут зависеть от обоих.

## Goals / Non-Goals

**Goals:**
- Одинаковые ответы на сервере и клиенте: модуль изоморфен.
- Детерминированность: целочисленная геометрия, никакой зависимости от порядка загрузки.
- Атомарные изменения мира с версией, понятной всем узлам.

**Non-Goals:**
- Движение и предсказание (P12), динамические объекты (P13, P23, P24), хранение и рассылка патчей (P07, P08).

## Decisions

### D1. Модуль `@duskmarch/asset-formats/world`
Хранилище, линия видимости и патчи работают с чанками и SHA-256 из `asset-formats`, поэтому размещены там. Параметры профиля (рост, подъём, высота глаз, дальность) передаются аргументами — модуль не зависит от `rules`.
- *Альтернатива — `rules`:* потребовало бы зависимости `rules → asset-formats`, которой нет в матрице P00.

### D2. Хранилище из чанков с копированием при записи
`RealmStore` держит массив декодированных чанков и для каждого — индекс объектов по клеткам (смещения `Uint16Array` и упорядоченный список). Запрос переводит клетку в чанк и локальные координаты делением на 32. Патч заменяет чанки целиком, поэтому чтения во время применения видят либо старые, либо новые данные.

### D3. Каталог объектов
Модель описывается высотой в шагах и ролью (`prop`, `obstacle`, `platform`). Флаги объекта в чанке уточняют роль: `impassable` — препятствие на `[h, h + height)`, `standable` — опора на `h + height`, `roof` — потолок на `h`, `blocks-sight` — препятствие зрению на `[h, h + height)`. Каталог синтетических моделей — в `synthetic/`; каталог контента придёт в P30.

### D4. Шаг
Из опор клетки назначения выбирается наивысшая с `s ≤ h + climb`, для которой выполняется размещение; спуск не ограничен. Порядок причин отказа: `out-of-realm`, `no-surface`, `too-high`, `blocked`, `corner`. Для диагонали обе ортогональные соседние клетки проверяются на непроходимость: флаг `impassable` или препятствие, пересекающее `[h, h + height)`.

### D5. Целочисленный DDA для линии видимости
Луч идёт от центра клетки к центру клетки. Пересечения границ сравниваются в целых числах: следующая граница по x — `(2i + 1)·|dy|`, по y — `(2j + 1)·|dx|`; равенство — точный проход через угол. Высота луча берётся в середине отрезка луча внутри клетки, поэтому прямой и обратный обход дают одинаковые клетки и высоты — проверка симметрична. Угол блокирует, только если обе ортогональные клетки блокируют зрение.

### D6. Высота глаз
По умолчанию `рост − 1` шаг (6 шагов, 1,5 м) над опорой источника и цели; вызывающий код может задать свою высоту точки (например, предмет на земле — 1 шаг).

### D7. Версия мира
`sha256(canonicalJson({ realm, chunks: [hash(0,0), hash(1,0), …] }))` в порядке `(cy, cx)`; хэш чанка — SHA-256 его канонических байтов `DMCK`. Совпадает с хэшами индекса мира пакета.

### D8. Патч и обратный патч
Операции применяются к копиям затронутых чанков по порядку; затем копии кодируются (это заодно проверяет значения), считаются хэши и версия, чанки заменяются одним присваиванием. Обратный патч строится из старых значений: `set-cell` для изменённых клеток и `add-object`/`remove-object` для объектов, базовая версия — новая версия.

### D9. Загрузка в `game-server`
`WORLD_PACK_DIR` — каталог пакета. Без него в `development` и `test` загружается синтетический `proving`; в `production` отсутствие переменной — ошибка конфигурации (код 78). Версия мира пишется в журнал и в поле `world` ответа `/readyz`.

## Architecture & Contracts

```ts
interface ObjectSpec { height: number; role: 'prop' | 'obstacle' | 'platform' }
class RealmStore {
  static load(index: WorldIndex, chunks: Map<string, Uint8Array>, catalog: Map<string, ObjectSpec>): RealmStore;
  readonly realm: { id: number; key: string }; readonly width: number; readonly height: number;
  version(): string;
  cell(x, y): CellData | undefined;
  surfaces(x, y): number[];            // по возрастанию
  ceiling(x, y, h): number | undefined;
  canPlace(x, y, h, height): boolean;
  step(from: { x, y, h }, dir: Direction, opts: { height, climb }): StepResult;
  lineOfSight(from, to, opts): SightResult;
  apply(patch: WorldPatch): PatchResult;
}
```

## Risks / Trade-offs

- **Память на большом плане** → 16 384 чанка по ~8 КиБ ≈ 130 МиБ на план 4096×4096; приемлемо для MVP, разбиение на партиции — P32.
- **Индекс объектов по клеткам пересчитывается при патче** → только для изменённых чанков.
- **Линия видимости на дальности 20** → не больше ~40 клеток на луч, без аллокаций в обычном режиме; трассировка выделяет память только по запросу.

## Migration Plan

Новый модуль. Откат — `git revert`; без `WORLD_PACK_DIR` разработка продолжается на синтетическом плане.
