# Спецификация: client/settings-profile

## Purpose

Определяет структуру, локальное хранение, облачную синхронизацию с аккаунтом и пользовательский интерфейс настроек клиента UO3 (графика, аудио, геймплей, интерфейс, базовые клавиши), включая разделение облачных и локальных параметров устройства, разрешение конфликтов версий, экспорт/импорт и раздел безопасности учётной записи.

## ADDED Requirements

### Requirement: Версионированная структура профиля настроек клиента и валидация границ
Профиль (`schemaVersion = 1`) MUST содержать строго валидируемые категории: `graphics` (пресет, зум `0.5..2.0`, pixel-snapping, FPS `30|60|120|uncapped`, крыши, круг прозрачности `80..300` px), `audio` (`0..100`, mute, mute при потере фокуса), `gameplay`, `interface` (`ru|en`, масштаб `0.75..1.5`, шрифт `12..20`) и `controls`. Нарушения MUST отклоняться с `422 PROFILE_VALIDATION_FAILED`.

#### Scenario: Принятие валидного профиля с граничными значениями UO:R
- **WHEN** клиент отправляет профиль с `zoom: 0.5`, `uiScale: 1.5`, `transparencyRadiusPx: 300`, `masterVolume: 0`, `locale: "ru"`
- **THEN** валидация проходит успешно, профиль сохраняется на сервере и применяется в клиенте

#### Scenario: Отклонение выхода за допустимые числовые диапазоны
- **WHEN** клиент или внешний запрос отправляет `zoom: 3.5` (выше канонического 2.0) или `masterVolume: 120` или неизвестное поле `injectedFlag: true`
- **THEN** API отклоняет запрос с HTTP `422`, кодом `PROFILE_VALIDATION_FAILED` и перечнем нарушенных путей полей

### Requirement: Разделение облачного профиля аккаунта и локальных переопределений устройства
Синхронизируемый профиль аккаунта SHALL хранить кросс-устройственные предпочтения (`audio`, `gameplay`, `interface`, `controls`, базовый графический пресет), тогда как аппаратно-зависимые параметры устройства (экспериментальный флаг WebGPU, локальное переопределение пресета графики и лимита FPS, подсказка последнего шарда, скрытие баннера PWA) MUST храниться строго локально в браузере и не передаваться в облачный профиль.

#### Scenario: Использование двух устройств с разной производительностью GPU
- **WHEN** игрок включает на настольном ПК локальное переопределение `rendererBackend = webgpu_experimental` и `fpsCapOverride = 120`, а затем открывает аккаунт на слабом ноутбуке
- **THEN** на ноутбук синхронизируются аудио, интерфейс, геймплей и привязки клавиш, а локальный рендерер ноутбука остаётся на безопасном `webgl2` без перезаписи

#### Scenario: Изоляция локального хранилища между разными аккаунтами в одном браузере
- **WHEN** пользователь А выходит из аккаунта и в том же браузере входит пользователь Б
- **THEN** настройки пользователя Б загружаются из его облачного профиля и отдельного пространства ключей, не наследуя локальные изменения пользователя А

### Requirement: Хранение и REST API профиля настроек аккаунта на сервере
API SHALL предоставлять защищённые (`scope = full`) эндпоинты `GET` (с выдачей по умолчанию и `ETag`/`304`), `PUT`, `PATCH` и `POST .../reset` по пути `/api/v1/account/client-profile`. Сериализованный JSON профиля MUST не превышать 65 536 байт (`413 PROFILE_PAYLOAD_TOO_LARGE`), а запись MUST ограничиваться 30 запросами/мин (`429 PROFILE_RATE_LIMITED`).

#### Scenario: Первый запрос профиля нового аккаунта с условным кэшированием
- **WHEN** новый аутентифицированный аккаунт впервые запрашивает `GET /api/v1/account/client-profile`
- **THEN** сервер возвращает HTTP `200` с `schemaVersion: 1`, `revision: 1`, заголовком `ETag: "rev-1"` и каноническими настройками по умолчанию
- **AND** повторный запрос с `If-None-Match: "rev-1"` возвращает HTTP `304 Not Modified`

#### Scenario: Отклонение чрезмерно большого тела профиля
- **WHEN** запрос `PUT /api/v1/account/client-profile` содержит JSON объёмом более 65 536 байт
- **THEN** сервер отклоняет запись с HTTP `413` и кодом `PROFILE_PAYLOAD_TOO_LARGE`

#### Scenario: Ограничение частоты записи профиля
- **WHEN** аккаунт отправляет 31-й мутирующий запрос профиля в течение 60 секунд
- **THEN** сервер возвращает HTTP `429`, код `PROFILE_RATE_LIMITED` и заголовок `Retry-After`

### Requirement: Оптимистичная конкурентность и разрешение конфликтов синхронизации
Мутирующие запросы (`PUT`, `PATCH`, `reset`) MUST передавать `expectedRevision` (или `If-Match`); при несовпадении сервер MUST вернуть `409 PROFILE_REVISION_CONFLICT` со снимком актуального профиля. Клиент SHALL автоматически сливать правки в разных категориях, а при конфликте одного поля — предлагать выбор между локальной и облачной версией.

#### Scenario: Автоматическое слияние непересекающихся правок с двух устройств
- **WHEN** устройство 1 меняет `audio.musicVolume`, а устройство 2 ранее изменило `interface.chatFontSize` (повысив ревизию сервера с 3 до 4)
- **THEN** после получения `409 PROFILE_REVISION_CONFLICT` клиент объединяет обе непересекающиеся правки на базе ревизии 4 и успешно фиксирует ревизию 5 без потери данных

#### Scenario: Интерактивное разрешение конфликта при изменении одного поля
- **WHEN** оба устройства изменили `interface.uiScale` (до `1.25` и `0.9`), и синхронизация возвращает `409 PROFILE_REVISION_CONFLICT`
- **THEN** интерфейс отображает диалог сравнения конфликтующих полей и позволяет пользователю явно выбрать локальную либо облачную версию с последующей фиксацией

### Requirement: Мгновенное локальное применение, отложенная синхронизация и офлайн-очередь
Изменение настройки MUST применяться локально немедленно (≤ 50 мс), а отправка на сервер SHALL группироваться с задержкой 1 500 мс (debounce). При офлайне или временном сбое `5xx` правки MUST сохраняться в локальной очереди с индикатором «Ожидает синхронизации» и автоматически отправляться после восстановления сети с экспоненциальным повтором.

#### Scenario: Коалесценция серии быстрых изменений ползунка громкости
- **WHEN** пользователь перетаскивает ползунок `audio.masterVolume` с 80 до 30, порождая 25 промежуточных значений за 800 мс
- **THEN** локальное значение обновляется немедленно на каждом шаге, а на сервер через 1 500 мс после остановки уходит ровно один запрос `PATCH` со значением 30

#### Scenario: Сохранение изменений в офлайн-режиме и автоматическая отправка
- **WHEN** пользователь изменяет настройки при отключённой сети браузера
- **THEN** изменения применяются локально и помечаются статусом «Сохранено локально, ожидает синхронизации»
- **AND** после восстановления сети клиент автоматически отправляет накопленные изменения с экспоненциальным повтором при временных ошибках

### Requirement: Межвкладочная синхронизация настроек в реальном времени
Изменение любой синхронизируемой или локальной настройки в одной открытой вкладке клиента того же аккаунта MUST распространяться на все остальные открытые вкладки того же origin в течение ≤ 100 мс, обновляя их отображение и состояние без отправки дублирующих запросов синхронизации на сервер.

#### Scenario: Синхронизация громкости и масштаба интерфейса между двумя вкладками
- **WHEN** пользователь включает `audio.muted = true` и меняет `interface.uiScale` на `1.25` в первой вкладке, пока открыта вторая вкладка того же аккаунта
- **THEN** вторая вкладка применяет новые значения за ≤ 100 мс и не инициирует повторный `PATCH` запрос к серверу

#### Scenario: Отсутствие утечки настроек между разными аккаунтами в соседних вкладках
- **WHEN** в первой вкладке происходит выход из аккаунта и вход в другую учётную запись
- **THEN** межвкладочный канал синхронизации фильтрует сообщения по `accountId` и не применяет настройки чужого аккаунта

### Requirement: Привязки базовых клавиш управления и обнаружение конфликтов
Вкладка управления SHALL позволять переназначать базовые игровые действия (передвижение, боевой режим, пейпердолл, рюкзак, окно навыков, журнал, цель на себя, последняя цель) с поддержкой модификаторов (`Ctrl`, `Alt`, `Shift`), блокируя системно зарезервированные небезопасные комбинации браузера. При назначении уже занятой комбинации интерфейс MUST немедленно подсвечивать конфликт с опциями обмена клавишами или отмены.

#### Scenario: Обнаружение конфликта и обмен клавишами при переназначении
- **WHEN** действие «Рюкзак» привязано к `Alt+I`, и пользователь назначает `Alt+I` действию «Пейпердолл»
- **THEN** интерфейс выделяет конфликт с «Рюкзак» и предлагает кнопки «Поменять местами», «Снять со старого действия» или «Отмена»

#### Scenario: Отклонение зарезервированных системных комбинаций браузера
- **WHEN** пользователь пытается назначить `Ctrl+W`, `Ctrl+T` или `F5` игровому действию
- **THEN** контрол перехвата клавиш отклоняет комбинацию с пояснением, что она зарезервирована браузером, сохраняя прежнюю привязку

### Requirement: Экспорт, импорт и миграция версий файла настроек JSON
Пользователь SHALL иметь возможность экспортировать профиль настроек в версионированный JSON-файл без токенов, email, `accountId` и локальных путей ОС, а также импортировать JSON-файл с предварительной проверкой схемы, автоматической миграцией поддерживаемых старых версий и сводкой изменений перед применением. Повреждённый или невалидный JSON MUST отклоняться без изменения текущих настроек.

#### Scenario: Безопасный экспорт и повторный импорт профиля
- **WHEN** пользователь экспортирует настройки в JSON-файл и импортирует его на другом устройстве
- **THEN** экспортированный файл не содержит PII и секретов, а импорт показывает сводку изменяемых категорий и после подтверждения применяет и синхронизирует профиль

#### Scenario: Отклонение повреждённого файла импорта настроек
- **WHEN** пользователь загружает файл с синтаксической ошибкой JSON, неподдерживаемой будущей `schemaVersion: 99` или невалидными полями
- **THEN** мастер импорта отображает код ошибки `ERR_SETTINGS_IMPORT_INVALID` с перечнем проблем, оставляя активные настройки нетронутыми

### Requirement: Сброс настроек по категориям и полный сброс профиля
Экран `/settings` SHALL предоставлять сброс отдельной категории (`graphics`, `audio`, `gameplay`, `interface`, `controls`) и полный сброс облачного профиля с подтверждением. Сброс MUST вызывать `POST /api/v1/account/client-profile/reset` с `expectedRevision` и сохранять локальные параметры устройства, если пользователь не выбрал их очистку.

#### Scenario: Сброс одной категории настроек без затрагивания остальных
- **WHEN** пользователь подтверждает «Сбросить категорию Аудио»
- **THEN** все параметры `audio` возвращаются к значениям по умолчанию, `revision` профиля увеличивается на 1, а пользовательские изменения `controls` и `interface` сохраняются

#### Scenario: Полный сброс облачного профиля с сохранением локальных параметров устройства
- **WHEN** пользователь подтверждает полный сброс облачных настроек без отметки «Очистить настройки этого устройства»
- **THEN** сервер сбрасывает облачный профиль к умолчанию, а локальный флаг `rendererBackend` на текущем устройстве остаётся прежним

### Requirement: Панель безопасности аккаунта и служебного статуса персонала в настройках
Вкладка безопасности в `/settings` SHALL интегрировать эндпоинты P04: сводку аккаунта и роли, привязку/отвязку OAuth, управление 2FA и резервными кодами, смену/установку пароля, смену email, список активных сессий с отзывом, пагинированную историю входов (90 суток) и переключатель `effectiveGameAccessLevel` для персонала `Counselor+`.

#### Scenario: Просмотр и отзыв чужой активной сессии в настройках безопасности
- **WHEN** аутентифицированный игрок открывает раздел активных сессий (`GET /api/v1/account/sessions`) и нажимает «Завершить» у другой сессии
- **THEN** клиент отправляет `DELETE /api/v1/account/sessions/:sessionId`, удаляет сессию из списка и показывает подтверждение без завершения текущей сессии

#### Scenario: Переключение игрового уровня доступа персоналом на дежурстве
- **WHEN** аккаунт уровня `GameMaster` переключает служебный режим на `Player` (`effectiveGameAccessLevel = 0`) в настройках
- **THEN** клиент отправляет `POST /api/v1/staff/effective-access-level`, обновляет индикатор эффективного уровня доступа в шапке оболочки и сохраняет максимальный уровень `GameMaster` для возврата

#### Scenario: Запрет отключения 2FA для сотрудника персонала в интерфейсе
- **WHEN** пользователь с уровнем доступа `Counselor` или выше открывает блок 2FA в настройках
- **THEN** кнопка отключения 2FA недоступна с пояснением обязательности двухфакторной защиты для персонала, при этом перевыпуск резервных кодов остаётся доступным
