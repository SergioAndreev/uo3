# Спецификация: content/localization

## Purpose

Спецификация определяет систему локализации UO3 для языков `ru` и `en`: структуру словарей и строгий контроль паритета в CI, CLDR-плюрализацию и проверку плейсхолдеров, движок `cliloc` с подстановками и 3-уровневым приоритетом BYOC/сервер/CC0, токенизированную сетевую доставку локализуемых сообщений и кэшируемые клиентские пакеты переводов.

## ADDED Requirements

### Requirement: Реестр локалей и структура файлов переводов

Система MUST поддерживать нормализованные локали `ru` и `en` (принимая `ru-RU`/`en-US` через нормализацию), разделённые по пространствам имён (`ui`, `items`, `creatures`, `regions`, `skills`, `spells`, `system`, `cliloc_ext`). Ключи MUST соответствовать `^[a-z0-9_.:-]{1,128}$` в UTF-8 без дублей (`ERR_LOC_DUPLICATE_KEY`).

#### Scenario: Нормализация региональных тегов языка
- **WHEN** клиент запрашивает локализацию с тегом `ru-RU` или `en-GB`
- **AND** сервер/движок выбирает соответствующий пакет переводов
- **THEN** тег нормализуется к поддерживаемой локали `ru` или `en` без ошибки

#### Scenario: Обнаружение дублирующегося ключа локализации
- **WHEN** два файла внутри пространства имён `ui` в локали `ru` определяют один и тот же ключ `ui.backpack.title`
- **AND** запускается компилятор локализации
- **THEN** компилятор отклоняет сборку с кодом `ERR_LOC_DUPLICATE_KEY`

### Requirement: Покрытие и паритет ключей между RU и EN в CI

Проверка в CI MUST гарантировать `100%` паритет ключей между `ru` и `en` для всех обязательных пространств имён, а также наличие всех `nameLocKey`/`descLocKey`, используемых в `content-definitions`. Отсутствующий перевод или пустая строка для непустого ключа в другой локали MUST завершаться ошибкой `ERR_LOC_MISSING_KEY`.

#### Scenario: Недостающий перевод в одной из локалей
- **WHEN** ключ `items.mythril_axe.name` добавлен в `en`, но отсутствует или пуст в `ru`
- **AND** запускается CI-проверка локализации
- **THEN** проверка падает с кодом `ERR_LOC_MISSING_KEY` с указанием локали и ключа

#### Scenario: Ссылка из YAML-определения на несуществующий ключ
- **WHEN** предмет в `content-definitions` указывает `nameLocKey: "items.ghost_blade.name"`, отсутствующий в словарях
- **AND** выполняется сквозная проверка контента и локализации
- **THEN** проверка возвращает ошибку `ERR_LOC_ORPHAN_REFERENCE`

### Requirement: Плюрализация CLDR/ICU для RU и EN и валидация плейсхолдеров

Форматтер MUST вычислять кардинальные формы CLDR: для `ru` — `one`, `few`, `many`, `other` (например, `1 предмет`, `2 предмета`, `5 предметов`, `21 предмет`, `11 предметов`), для `en` — `one`, `other`. Множества именованных параметров `{param}` между `ru` и `en` MUST совпадать (`ERR_LOC_PLACEHOLDER_MISMATCH`), а синтаксические ошибки ICU MUST отклоняться с `ERR_LOC_SYNTAX_INVALID`.

#### Scenario: Корректное склонение числительных в русской локали
- **WHEN** строка `ui.loot.gold_coins` форматируется для локали `ru` со значениями `1`, `3`, `5`, `11`, `21`, `24`
- **AND** шаблон содержит формы `one`/`few`/`many`/`other`
- **THEN** форматтер выбирает `one` для `1` и `21`, `few` для `3` и `24`, `many` для `5` и `11`

#### Scenario: Расхождение набора плейсхолдеров между языками
- **WHEN** `en`-строка содержит `{player}` и `{amount}`, а `ru`-строка содержит только `{player}`
- **AND** выполняется сборка словарей
- **THEN** компилятор отклоняет пакет с кодом `ERR_LOC_PLACEHOLDER_MISMATCH`

### Requirement: Поддержка формата Cliloc и подстановок ~N_label~

Движок `cliloc` MUST разрешать числовые идентификаторы (`1..9999999`), подставляя аргументы по маске `~1_NAME~`..`~8_VAL~` из строки с разделителем `\t`, и рекурсивно раскрывать аргументы вида `#<clilocId>`. Глубина рекурсии `#<id>` MUST ограничиваться `4` уровнями; циклы MUST отклоняться при валидации с `ERR_LOC_CLILOC_CYCLE`.

#### Scenario: Многопараметрическая подстановка Cliloc с вложенным ID
- **WHEN** шаблон cliloc `1042971` равен `"Вы видите ~1_AMOUNT~ ~2_ITEM~."`, а аргументы равны `"5\t#1023821"` (где `1023821` = `"золотых монет"`)
- **AND** выполняется рендеринг сообщения в локали `ru`
- **THEN** итоговая строка равна `"Вы видите 5 золотых монет."`

#### Scenario: Циклическая ссылка внутри Cliloc-аргументов
- **WHEN** статический или тестовый cliloc-запись `9000001` ссылается на `#9000002`, который ссылается обратно на `#9000001`
- **AND** выполняется проверка или рендеринг с ограничением глубины `4`
- **THEN** статическая валидация возвращает `ERR_LOC_CLILOC_CYCLE`, а рантайм обрывает рекурсию без переполнения стека

### Requirement: Слой объединения синтетических и клиентских (BYOC) Cliloc

Резолвер клиента MUST применять строгий порядок приоритета: (1) кастомные/переопределённые записи шарда из `cliloc_ext`, (2) локально импортированный пользовательский `cliloc` из браузерного хранилища (если подключён), (3) встроенный синтетический CC0-словарь. При отсутствии ID во всех слоях резолвер MUST возвращать безопасный маркер `[#cliloc:<id>]`.

#### Scenario: Приоритет серверного переопределения над локальным BYOC-файлом
- **WHEN** клиент импортировал локальный файл `cliloc` с записью `500001`, а серверный пакет `cliloc_ext` содержит переопределение `500001`
- **AND** интерфейс запрашивает текст по `clilocId = 500001`
- **THEN** отображается строка из `cliloc_ext` сервера

#### Scenario: Фолбэк на встроенный CC0-словарь и безопасная заглушка
- **WHEN** пользователь играет без импортированных классических файлов клиента и запрашивается известный синтетический ID или отсутствующий ID `9876543`
- **AND** выполняется разрешение строки
- **THEN** для известного ID возвращается CC0-текст, а для отсутствующего — `"[#cliloc:9876543]"` без исключения

### Requirement: Серверная репликация Cliloc-сообщений с аргументами (Tokenized Localized Text)

При отправке системных сообщений, уведомлений навыков и речи NPC сервер MUST передавать компактный токенизированный пакет (`clilocId` или `locKey`, массив из `≤ 8` аргументов длиной `≤ 256` символов каждый, цвет и канал) вместо готовой отрендеренной строки. Это MUST позволять каждому игроку в одной комнате видеть сообщение на языке своего профиля.

#### Scenario: Разный язык отображения одного события у двух игроков
- **WHEN** NPC произносит системную реплику с `clilocId = 1005001` рядом с игроком A (профиль `ru`) и игроком B (профиль `en`)
- **AND** сервер рассылает токенизированный пакет в пределах радиуса слышимости
- **THEN** клиент игрока A отображает русскую фразу, а клиент игрока B — английскую

#### Scenario: Защита протокола от переполнения аргументов
- **WHEN** попытка сформировать локализованное сообщение передаёт `9` аргументов или аргумент длиннее `256` символов
- **AND** срабатывает валидация протокола
- **THEN** сообщение отклоняется или усекается до лимитов до сериализации в сетевой кадр

### Requirement: Инкрементальные клиентские бандлы локализации с хэшированием

Пайплайн сборки MUST генерировать версионированные сжатые пакеты локализации по языкам (`loc.<locale>.<locHash>.json`) и индексный манифест для отдачи с заголовком `Cache-Control: immutable`. Размер базового пакета локализации (`ui` + `system` + `skills` + `spells`) MUST NOT превышать `512 KiB` в сжатом виде (`gzip`).

#### Scenario: Кэширование неизменного пакета локализации по locHash
- **WHEN** клиент загружает пакет локализации для `ru` по `locHash`, полученному в манифесте
- **AND** тот же `locHash` остаётся активным при повторном входе
- **THEN** клиент использует локально кэшированный пакет без повторной сетевой загрузки

#### Scenario: Превышение бюджета базового пакета локализации
- **WHEN** сжатый размер базового пакета локализации для одной локали превышает `512 KiB` (`524 288` байт)
- **AND** завершается сборка бандла
- **THEN** сборщик завершает шаг с ошибкой `ERR_LOC_BUNDLE_TOO_LARGE`

### Requirement: Псевдолокализация и проверка переполнения UI

Пайплайн MUST поддерживать генерацию синтетической локали `pseudo` из `en`, удлиняя видимый текст на `+35%` с обрамлением `[!! ... !!]` и сохраняя неприкосновенными все `{placeholders}`, ICU-селекторы и токены `~N_label~`/`#<id>`. Целостность токенов в `pseudo` MUST проверяться автоматически.

#### Scenario: Сохранение плейсхолдеров при расширении текста в псевдолокализации
- **WHEN** генератор `pseudo` обрабатывает строку `"Craft {count} {item}?"`
- **AND** добавляет удлинение `+35%` для проверки вёрстки гампов
- **THEN** токены `{count}` и `{item}` остаются без изменений внутри `[!! ... !!]`

#### Scenario: Сохранение токенов Cliloc и проверка длины при псевдолокализации
- **WHEN** генератор `pseudo` обрабатывает запись `cliloc_ext` с подстановкой `~1_NAME~` и ссылкой `#102030`
- **AND** запускается автоматическая проверка целостности токенов
- **THEN** длина отображаемой части увеличена на `35%`, а токены `~1_NAME~` и `#102030` полностью сохранены

### Requirement: Экспорт/импорт для переводчиков и защита от XSS/инъекций

Компилятор локализации MUST экранировать или отклонять небезопасную разметку и управляющие последовательности (`<script`, `javascript:`, небалансные теги допустимого подмножества разметки гампов) с кодом `ERR_LOC_UNSAFE_MARKUP`. Инструментарий MUST поддерживать экспорт диффа новых/изменённых ключей в детерминированный JSON/CSV для переводчиков.

#### Scenario: Блокировка небезопасного тега в файле перевода
- **WHEN** строка перевода содержит `<script>alert(1)</script>` или непарный тег форматирования
- **AND** запускается компилятор локализации
- **THEN** сборка падает с ошибкой `ERR_LOC_UNSAFE_MARKUP`

#### Scenario: Экспорт только непереведённых или изменённых ключей
- **WHEN** переводчик запускает экспорт диффа между базовой версией и веткой с `15` новыми ключами
- **AND** указывает фильтр целевой локали `ru`
- **THEN** формируется детерминированный файл ровно с `15` строками, сохраняя эталонную `en`-версию рядом
