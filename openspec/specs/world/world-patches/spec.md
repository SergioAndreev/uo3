# world/world-patches Specification

## Purpose
Определяет изменение данных плана Duskmarch без перезапуска: декларативные патчи над клетками и объектами, версию мира, проверку конфликтов, атомарное применение и откат.

## Requirements

### Requirement: Версия мира
Версия плана MUST быть SHA-256 канонического JSON из ключа плана и упорядоченного по `(cy, cx)` списка хэшей чанков. Одинаковые данные SHALL давать одинаковую версию независимо от порядка загрузки чанков.

#### Scenario: Версия загруженного плана
- **WHEN** один и тот же пакет загружается дважды
- **THEN** версии совпадают и состоят из 64 hex-цифр

### Requirement: Операции патча
Патч MUST содержать идентификатор, базовую версию плана и список операций: `set-cell` (поверхность, высота, флаги, оттенок одной клетки), `fill` (те же поля для прямоугольника), `add-object` и `remove-object` (по ключу, координатам и высоте). Значения MUST проходить те же проверки, что и при кодировании чанка; ошибка SHALL отклонять весь патч с кодом `PATCH_INVALID` и номером операции.

#### Scenario: Недопустимая высота
- **WHEN** патч содержит `set-cell` с высотой `2 000`
- **THEN** патч отклоняется с `PATCH_INVALID` и номером этой операции

### Requirement: Конфликты
Патч с базовой версией, отличной от текущей, MUST отклоняться с кодом `PATCH_BASE_MISMATCH`. `remove-object` для отсутствующего объекта MUST отклоняться с кодом `PATCH_CONFLICT`.

#### Scenario: Устаревшая база
- **WHEN** два патча созданы от одной версии и первый уже применён
- **THEN** второй отклоняется с `PATCH_BASE_MISMATCH`

### Requirement: Атомарное применение и откат
Применение MUST сначала строить копии затронутых чанков, затем заменять их одним шагом; при ошибке в любой операции хранилище SHALL остаться без изменений. Результат применения MUST содержать новую версию, перекодированные чанки `DMCK` и обратный патч, применение которого возвращает предыдущую версию.

#### Scenario: Ошибка в середине патча
- **WHEN** третья из пяти операций патча конфликтует
- **THEN** ни одна операция не применена, версия плана прежняя

#### Scenario: Откат
- **WHEN** патч применяется, а затем применяется его обратный патч
- **THEN** версия плана и байты всех чанков совпадают с исходными

### Requirement: Запросы видят изменения
После применения патча запросы опор, размещения, шага и линии видимости MUST использовать новые данные без перезагрузки хранилища.

#### Scenario: Новая стена
- **WHEN** патч ставит клетку с флагами `impassable` и `blocks-sight` между двумя точками открытого поля
- **THEN** шаг в эту клетку отклоняется, а линия видимости через неё блокируется
