# Данные мира в памяти

Подпуть `@duskmarch/asset-formats/world`. Модуль изоморфен: сервер авторитарно проверяет действия, клиент (P12) повторяет те же запросы для предсказания. Параметры героя (рост, подъём, высота глаз, дальность) передаёт вызывающий код из профиля правил.

## Хранилище

```ts
const store = RealmStore.fromPack(manifest, (path) => read(path), SYNTHETIC_CATALOG);
store.surfaces(12, 4); // [0, 9] — пол и вершина ящика
store.ceiling(12, 4, 0); // 6
store.canPlace(12, 4, 0, { height: 7 }); // false
store.step({ x: 3, y: 4, h: 0 }, 2, { height: 7, climb: 2 }); // { ok: true, x: 4, y: 4, h: 0 }
```

- **Каталог объектов:** ключ модели → высота в шагах и роль `prop`, `obstacle` или `platform`. Флаги объекта в чанке уточняют роль: `impassable` — препятствие, `standable` — опора на вершине, `roof` — потолок на основании, `blocks-sight` — препятствие зрению.
- **Опоры** — пол клетки с флагом `standable` и вершины платформ, по возрастанию. **Потолок** — наименьшее основание препятствия, потолка или платформы выше заданной высоты.
- **Шаг** выбирает наивысшую опору не выше `h + climb`, на которой сущность помещается. Причины отказа: `out-of-realm`, `no-surface`, `too-high`, `blocked`, `corner` (диагональ срезает угол непроходимой клетки).

## Линия видимости

`lineOfSight(store, from, to, { fromEye, toEye, range, trace })`. Луч идёт от центра клетки к центру, пересечения границ сравниваются в целых числах, высота луча — в середине отрезка внутри клетки, поэтому проверка симметрична. Блокируют: клетка с `blocks-sight` (`cell`), объект с `blocks-sight` на высоте луча (`object`), пол выше луча (`terrain`), проход точно через угол между двумя закрытыми клетками (`corner`). Исходная и целевая клетки не блокируют. Дальность по Чебышёву — 20 по умолчанию (`range`); другой план — `realm`.

## Патчи и версия

```json
{ "id": "patch.example", "base": "<версия>", "ops": [{ "op": "set-cell", "x": 10, "y": 10, "flags": ["impassable"] }] }
```

Операции: `set-cell`, `fill`, `add-object`, `remove-object`. `applyPatch` проверяет базовую версию (`PATCH_BASE_MISMATCH`), значения (`PATCH_INVALID` с номером операции) и наличие удаляемых объектов (`PATCH_CONFLICT`), применяет всё или ничего и возвращает новую версию, перекодированные чанки и обратный патч. Версия плана — SHA-256 канонического JSON из ключа плана и хэшей чанков в порядке `(cy, cx)`.

## Игровой сервер

`WORLD_PACK_DIR` — каталог пакета. Без него вне `production` загружается синтетический `proving`; в `production` переменная обязательна (код 78). Версия мира — в журнале старта и в поле `world` ответа `/readyz`. Отладка: `asset-tool query <каталог> --at x,y [--to x,y]`.
